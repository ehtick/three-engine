# World export contract

World's version-1 embedded document remains the authored source in scenes, prefabs and exported levels. The exporter rewrites a detached copy; it does not bake away edits or serialize generated texture URLs into that document.

`resources.materials` maps supported appearance roles to ordinary `.mat` paths. `resources.surfaceMaps`, when supplied, contains all three `grass`, `soil` and `rock` roles, each with `{ albedo, height, size: [metresX, metresZ] }`. These use the normal engine asset resolver. The shared `src/engine/world/worldAssetRefs.js` walk covers resource roles, provider overrides (including native schemas, Terrain layers/scatter, Mesh slots and variants), material edit values, pin snapshots and authored feature props. Export routes `.mat` files through its existing texture rewrite; scene preloading discovers their nested images through `expandMaterialAssets`.

Without replacement surface maps, the loader imports `worldBuiltinSurfaces.js`. Its six `new URL(..., import.meta.url)` references are module-owned Vite assets, with exact original dimensions and 6,716,074 bytes of original CC0 maps. Source metadata and attribution live in `src/modules/world/assets/`. Vite assigns relative hashed player URLs, so deployment under a nested static-host folder works without a project path, `/scripts` import, public study manifest or network download. The compatibility study loader re-exports this production implementation. Runtime trimming excludes the study's duplicate `public/world-study/` payload.

Export examines components across every shipped scene and reachable prefab, infers their module definitions, and resolves required dependencies before writing `scene.modules` and selecting player chunks. This also covers a World in a level that was never opened in the editor. Provider dependencies remain registered in the catalog even when the editor's explicit selection is empty. The complete build closure is written to each exported scene for subsequent level loads.

CPU validation: `node --test tests/world-export.test.mjs`, `npm run test:build`, and `node scripts/run-scene-manager-test.mjs`. The World tests gate colliding filenames, authored IDs, read-only discovery, nested `.mat` image preloading, project asset resolution, map color spaces, texture disposal on success/failure, exact default hashes/dimensions and runtime asset trimming.

Actual player gate: build with `npm run build:player`, start Vite, then run `node scripts/run-world-export-smoke.mjs http://127.0.0.1:5401`. Run only with the serial GPU slot. The renderer-free editor fixture invokes the real exporter; its Tauri adapter materializes the exact requested output in an external scratch directory. A separate page opens the unmodified player under `/nested/game/`, served only from that output. Default and replacement-map scenes must generate native providers, preserve an authored roof edit, resolve the custom material's image into a real ground mesh and render at the portable eight-storage-buffer limit without dev URLs or missing files. The receipt and screenshots land in `artifacts/world-export/`; the exact scratch project/export are retained for inspection.

The CPU tests do not create GPU pipelines. A successful player receipt is required separately; neither these packaging changes nor a player smoke certify the final landscape visual target or production GI/water composition.

## First production export receipt

The 2026-09-12 player template built at `15:46:24.531Z` passed the real export/player gate: six inferred modules, eight copied user assets, 31 successful/housekeeping requests, and no runtime or WebGPU validation errors. Both scenes reached World `Ready` with a native Terrain wrapper at the portable eight-storage-buffer cap. The actual default terrain draw bound all six supplied maps; the optional material's rewritten diffuse image reached the wrapper's borrowed base. Screenshots and actual fragment WGSL are retained under `artifacts/world-export/`.

The first screenshot review exposed a silent native material ownership failure despite correct packaging: Mesh's asynchronous extra-slot load completed one microtask after Terrain attached and replaced its material with default white. The retained diagnostic export proves that the live material was a white `MeshPhysicalNodeMaterial` with no color node; reinstalling Terrain's existing wrapper changed 498,237 pixels (RGB mean absolute difference 48.291). The direct generated material and a new wrapper clone reproduced the wrapper result, ruling out a missing texture or first-compilation shader problem. The native Mesh guards now respect Terrain ownership, and the export smoke requires actual wrapper identity plus the six bound maps, so a white terrain cannot pass on asset counts alone. `scripts/run-world-export-diagnostic.mjs` reproduces this investigation from a retained exact export without a source-server fallback.

The harness snapshots a completed player template into its external scratch directory before export, because a live editor may rebuild `dist-player` while runtime files are being copied. The receipt records that template's build timestamp. These receipts cover the foundation before the subsequent variable-layout work; rerun after changing the World generator/runtime.
