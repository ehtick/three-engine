# Engine development invariants

## Response style

Respond short: main thesis first, 2-3 sentences with the key information. Detail belongs in plan docs and memory, not in chat replies.

## WebGPU GI binding budget

- Every GI compute shader must stay within WebGPU's portable limit of **8 storage buffers per shader stage** (`maxStorageBuffersPerShaderStage = 8`).
- Do not fix binding validation errors by requesting a device limit of 16. The engine must continue to run on adapters that expose only the portable default.
- Count bindings on the fully composed TSL graph, not per helper function. A deferred pass that invokes one helper for each of three cascades can bind each cascade's buffers independently; three buffers per cascade therefore becomes nine and fails pipeline creation.
- Prefer packing related data into an existing storage buffer, reusing an already-bound buffer/bit field, or moving read-only sampled data into textures. The probe and light data are intentionally packed for this reason.
- After any GI buffer or TSL sampling change, run the runtime WebGPU smoke test. A Vite build does not create GPU pipelines and cannot detect binding-limit failures:

  1. Start Vite locally.
  2. Run `node scripts/run-gpu-page.mjs http://127.0.0.1:<port>/scripts/gi-gpu-smoke.html 70000`.
  3. Require `GI-SMOKE PASS` and no WebGPU validation errors.

The recurring failure signature is:

```text
The number of storage buffers (9) in the Compute stage exceeds the maximum per-stage limit (8).
```

Treat this as a graph binding-budget regression, not as a reason to raise device limits.

The unification is the point: an imported HDRI used to spawn an `environment` COMPONENT on an entity, so the viewport showed an HDRI while Scene Settings said "Cube map: None" and none of its knobs (intensity, rotation, sky blur) reached it. `test:sky` is the headless half — extension dispatch, and that a load NEVER rejects (a moved file must leave the flat background, not throw out of a settings apply). `smoke:hdri` is the real-WebGPU half, and gates the failure that is a picture rather than an error: an equirect assigned without `EquirectangularReflectionMapping` renders as a stretched rectangle, and a v-flip renders upside down, so it paints the panorama's top half red and its bottom half green and looks up and down. | `npm run test:post-ssr` | The SSR post node's reach (`modules/postprocessing/postGraph.js`). **`SSRNode.maxDistance` is `uniform(1)` — one WORLD UNIT** (SSRNode.js:168), and the builder never assigned it, so the effect reflected a footstep of floor and nothing beyond. The first test pins the addon's own default so a three upgrade can't quietly move the premise. Also gates the composite's contract: SSR hands back a contribution PREMULTIPLIED by `(1 - d/maxDistance)²`, so a hit near the range limit is a *black* sample, not an absent one — mixing beauty toward it on a binary `alpha > 0` mask painted the surface black over exactly the band where the GI/env fallback should have taken over. And the hot-param path: `updateParams` was a stub while the component early-returned on signature equality, so **every numeric post param was inert** until some structural edit forced a recompile — the test drags the sliders and asserts the uniforms move, that the signature does NOT, and that a cleared prop returns to its default. Plus: SSR compiles downstream of another effect (the addon infers its camera from `colorNode.passNode`, which only the raw scene pass carries, and throws otherwise). And the one that actually made a mirror black: **the matParams MRT must follow `metalnessNode`/`roughnessNode`, not the scalars** — `TSL.metalness` is a `materialReference` to the JS scalar, while `MeshStandardNodeMaterial.setupVariants` prefers the node, so every shader-graph material (graph metalness 1 over a stale asset scalar of 0) reached SSR as a rough dielectric and the addon's `metalness <= 0` discard threw away all of its pixels. | `npm run test:occlusion` | Hi-Z occlusion culling (`engine/culling/`). Most of it asserts that things are still DRAWN, because the failure mode is objects that vanish. The section to know about is **"the readback arrives in the pyramid's row order"**: `projectSphere` maps NDC y to `v = y*0.5+0.5`, so `v` runs UP and `DepthPyramid.build` needs row 0 at the BOTTOM — which only `gl.readPixels` gives you. A WebGPU readback is top-down, and feeding it through unflipped mirrors every depth test about the screen centre: no error, no blank frame, just objects culled against whatever is on the opposite side of the view. That shipped, and was reported as "meshes disappear in front of the camera". The last check reproduces it — a wall across the bottom half, an object high on screen with only sky in front, culled by the un-flipped buffer and kept by the flipped one. Also gates that culling is configured on the **camera**, not the scene: `CameraComponent` owns `frustumCulling` / `occlusionCulling` / `occluderMinSize` / `occlusionBias` / `cullShadowCasters`, `occlusionCulling` is TRI-STATE (`inherit` keeps `settings.performance.occlusionCulling` meaning what it always meant, so no pre-existing scene changed behaviour), and the **editor viewport camera is not an entity** — it falls back to the scene's first enabled camera so the viewport culls the way the build will. No GPU; the depth PASS itself lives in `npm run smoke:occlusion`. |
| `npm run test:readback` | Reading a render target back as an image (`engine/renderTargetImage.js`), the one place that knows the two backends disagree about **both** row padding and row order. WebGPU pads rows to 256 bytes and `copyTextureToBuffer` preserves texture order (**row 0 = TOP**); WebGL packs tightly and `gl.readPixels` counts **from the bottom**. Both ways of getting it wrong return an image rather than an error — the wrong order is a perfect picture upside down, the wrong padding is a progressive shear — and the first one shipped: every `viewport.screenshot` and every `.geom` thumbnail was inverted, because WebGL's flip had been hand-copied into the WebGPU path. Also pins that the last row is SHORT by design (three sizes the buffer `(h-1)*paddedRow + rowBytes`) so a reader must clamp, and that an unknown backend is assumed to be WebGPU. Fake renderer, no GPU, instant. |
