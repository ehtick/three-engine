# Engine development invariants

## Response style

Respond short: main thesis first, 2-3 sentences. Detail belongs in plan docs and memory.

## Directional shadow performance

Shadow replacement must be cheap with **moving lights** (rotating Sponza sun); fixed-light camera-yaw cache hits don't satisfy it. Measure full CPU/frame cost (texture copies, queue submissions, traversal, caster classification) + GPU raster. Changed clipmap projection = one native full render per level, no static-cache capture/copy. Preserve crispness, native alpha/deformation, immediate light response; never hold a stale moving-light shadow.

## WebGPU GI binding budget

- Every GI compute shader stays within **8 storage buffers per shader stage** (portable limit). Never fix binding errors by raising device limits.
- Count bindings on the composed TSL graph, not per helper (3 buffers × 3 cascades = 9, fails). Fix by packing/reusing buffers or moving read-only data to textures.
- After any GI buffer/TSL change run the runtime smoke (Vite builds don't create pipelines): start Vite, `node scripts/run-gpu-page.mjs http://127.0.0.1:<port>/scripts/gi-gpu-smoke.html 70000`, require `GI-SMOKE PASS`, no validation errors. "storage buffers (9) … exceeds … (8)" = graph budget regression.
